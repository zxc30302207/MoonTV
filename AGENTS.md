# Repository Guidelines

## Project Structure & Key Paths
- `src/app`: Next.js app router pages and API routes (admin under `api/admin`, search/play pages under `play`, `search`, `page.tsx`).
- `src/components`: Shared UI pieces (selectors, menus, nav, etc.).
- `src/lib`: Core logic (config, downstream search, types, versioning, danmaku helpers).
- `public`: Static assets (icons, service worker bundles).
- `scripts`: Build-time helpers (`generate-manifest.js`, `generate-runtime.js`).
- Config inputs: `config.json` (source list/cache), `.env.local` (secrets), `runtime` artifacts generated by scripts.

## Build, Test, and Dev Commands
- `pnpm install`: Install dependencies (use pnpm 10.x+).
- `pnpm dev`: Local dev server (runs manifest/runtime generation first).
- `pnpm build`: Production build (invokes manifest/runtime generation).
- `pnpm start`: Start built app.
- `pnpm lint`: ESLint (Next.js config) with Prettier/Tailwind plugin.
- `pnpm test`: Jest test suite.
- `pnpm format`: Prettier write-all; `pnpm format:check` to verify.

## Coding Style & Naming Conventions
- TypeScript-first; prefer explicit types and avoid `any`.
- 2-space indentation; keep imports sorted (eslint-plugin-simple-import-sort).
- Components: PascalCase filenames in `src/components`; hooks/utilities in `src/lib` use camelCase exports.
- React: Functional components, hooks only in components/hooks; keep side effects in `useEffect`.
- Styling: TailwindCSS; prefer utility classes over inline styles.
- Keep console noise out of production paths; let lint rule guide.

## Testing Guidelines
- Framework: Jest + @testing-library/react.
- Place tests near code or in `__tests__`, using `*.test.ts(x)` naming.
- Run `pnpm test` before PRs; add focused tests for new logic (API handlers, selectors, config transforms).

## Commit & PR Guidelines
- Commit style follows Conventional Commit patterns (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`). Keep messages imperative and scoped.
- PRs: include summary of changes, test results, and screenshots/GIFs for UI tweaks. Note breaking changes or config migrations explicitly.

## Configuration & Secrets
- Secrets in `.env.local` (never commit). Common vars: `NEXT_PUBLIC_*`, `DOCKER_ENV`, `USERNAME`, `PASSWORD`.
- Source/config seeds in `config.json`; database/runtime config handled via `src/lib/config.ts` and `runtime` generation scripts.
- For Vercel, main branch push auto-deploys—verify env vars there.

## Agent Tips
- If lockfile changes, keep `pnpm-lock.yaml` in sync with `package.json`.
- Husky hooks are installed; if skipped locally, ensure lint/tests still run.
- When regenerating runtime/manifest manually: `pnpm gen:manifest && pnpm gen:runtime` before build.
