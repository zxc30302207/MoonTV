## 去廣告安全原則

去廣告以保留正片為優先。共同的 HLS 處理流程支援各來源，不以單一站名決定刪除。

- 只刪除經畫面核實且完整符合的廣告素材序列，或有可靠邊界的明確廣告標記
- 不因 `ad`、`gg`、`promo` 等檔名、換網域、不同資料夾、短片段、重複畫面或一般轉場就刪除
- 無法安全處理的加密、即時播放清單、多音軌／多畫質未對齊清單或不明片段保持原樣
- 保留所有非廣告片段的網址和順序，並維持 KEY、MAP、原始 AES IV 與 BYTERANGE 位移
- 重新導向後以最終 URL 解析相對路徑；Hls.js、原生 HLS 與預取共用安全規則
- AD 提示顯示實際識別結果。已開啟不代表每部影片都存在可安全分離的廣告

## 版本與驗證

`VERSION.txt`、介面版本與變更日誌同步為 4.2.1。更新檢查繞過 HTTP 快取，拒絕無效回應，支援版本前綴與自訂後綴；真正較新的上游版本仍會提示。

新增回歸涵蓋：版本同步、廣告與正片保留、加密和位元組範圍、轉址、播放快取、登出競態、批次下載取消／重複開始／續傳、追更移除競態、Supabase 權限與匯入驗證。

依賴安全更新維持 Next 15、React 18 與既有 Supabase 介面。正式依賴稽核為 0 漏洞；開發工具仍有 `braces`、`sprintf-js`、`postcss-selector-parser` 三項已知公告，沒有在此次功能整合中強行升級工具鏈主版本。

## 回復方式

整合以原自訂分支為父提交，完整記錄上游來源 SHA；GitHub 連接器以單一原子提交發佈相容後的程式，不匯入上游整段歷史。需要程式回復時，可建立 `git revert <整合提交>` 的新提交，或使用部署平台保留的原版本；不得透過清空資料庫回復程式版本。
